# ASOBooN｜取消済み番号の追跡停止とチョコミント復元

日付：2026-11-11

## 対応理由

- AirWAITで取り消された受付番号について、ミニアプリが再読込・画面移動後も保存番号を使い、自動照合を繰り返していた。
- 上部ヘッダー・画面下部の固定ナビゲーションで、以前のチョコレートらしい見た目が弱くなっていた。

## 仕様

1. 本人キャンセル成功、またはAirWAITから明示的に `state: canceled` が返された場合、その受付番号・営業日・予約IDをローカルに記録して**自動ポーリングを完全停止**する。再読み込み・他タブからの戻りでも取り消し済みの番号を自動取得しない。
2. 受付が見つからない場合、**取消済みだと断定しない**。本人照合で見つからなければ直ちに、`reservationStatus`で未発見が続く場合は最大3回の照合後に自動追跡を停止する。受付番号は表示用に残し、「今すぐ更新」を押せば本人が再確認可能。
3. 新しい受付が作成された場合、以前の取消番号と照合が一致しないので、**新しい受付番号での最新状態取得は通常どおり再開**する。待機中や呼出中の通常ポーリングは継続。
4. HOMEの仮表示処理も取り消し済み番号を再び「確認中」として扱わず、取消状態を表示する。
5. 上部ヘッダーと下部メニューを**濃いチョコレートブラウン＋ミント**のグラデーションで統一。チョコチップ・とろけた装飾は純CSS、押下領域の上に透明な操作妨害物を置かない。既存ロゴ・下部4タブは維持。
6. LINE本人確認、取消APIの許可条件、保存した受付IDの真正性、AirWAITの受付作成・予約枠数・混雑予想・料金は変更しない。

## 検証

- 新規7ブラウザケース：本人取消後の画面再読込、AirWAIT側取消、未発見の自動停止と手動再開、新受付への更新、HOMEの取消状態、幅320/390/430pxチョコレート意匠・タップ可能性に合格
- Productionバンドルの初期ロード上限は**145KBを維持**し、ビルド `--check` 合格
- 全Productionブラウザ回帰テスト：**173／173件合格**（約2.3分、`/tmp/boon-cancel-choco-full-standard.log`）
- 本番PR・CI・Pages・実機：最終確認後に追記する

注意：未知の番号を「取消済み」と推測することはない。公開ブラウザでの正常表示を確認しても、LINEアプリ内の実際の取消操作やAirWAIT操作履歴を使った実機検証の代わりにはならない。

- CI のHOMEフロー静的検査も旧来の無限再照合期待値を撤廃し、新しい最大3回・取消番号の追跡停止を契約として検証するよう変更。
