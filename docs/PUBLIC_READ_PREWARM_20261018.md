# ASOBooN 先読みキャッシュ｜実装・本番導入手順

**状態：本番は未変更。PR検証中／デフォルトOFF。**

## 目的と動作

Cloudflare Workerの既存の毎分cronで公開情報を事前取得し、D1とエッジキャッシュへ保存。お客様の端末がAirWAITの応答を待つ回数を減らす。

- 営業日：JST 19:00を運用日の切替として利用。朝9:15以降、営業中と19:00直後に先読み。既存の30分TTLを守るのでGoogleカレンダーへ毎分アクセスしない。
- 受付・混雑残数：営業日9:15から営業時間終了付近まで約1分ごとに取得。休館日と営業時間外は更新しない。
- お客様の表示：D1の検証済み情報を優先し、20秒のエッジキャッシュも利用。45秒以内のスナップショットを毎回AirWAITに問い合わせ直さない。障害時は古い情報を最新と偽らず、既存の期限切れ制御を維持。
- 受付番号の発行、LINE認証、通知、キャンセル、呼出掲示板には手を加えない。

## 重要：オプトイン・ロールバック

安全確認が完了するまでは公開Workerの環境変数 PUBLIC_READ_PREWARM_ENABLED は 0（または未設定）にする。OFFでは旧挙動を維持する。

GitHub Actionsの deploy-miniapp-v2-production-gateway から手動実行する場合：
- mode: live（受付を停止しない）
- public_read_prewarm: on（準備と承認が完了してから）
- 本番環境レビュアーによる承認後、健康状態で受付発行・通知・キャンセルが有効なことを確認。

停止する場合は mode: live / public_read_prewarm: off で再デプロイ。mode: dark は受付を停止するため、通常の切り戻しに使わない。

## 検証

- 隔離されたFakeWorld／D1で、Cron 1回の事前取得後に100件の同時読み込みを実施。追加のAirWAITリクエスト0件、予約新規発行0件。
- 休館日と営業時間外の外部残数取得0件。オプトインOFFでは既存動作を変更しない。
- 全自動テスト、GitHubのブラウザE2E、本番公開後の実測と監視をそれぞれ実施する。

## 本番移行前の追加確認

AirWAITのAPI使用量とCloudflareのCron実行コスト、表示鮮度、実利用での読み込み時間（p50/p95）、GASのカレンダー日付切替、前日・当日の受付枠変更を確認する。

**対象外**：本人確認方式の変更（PR #108の検討事項）、10分キャッシュの受付枠有効・無効、呼出掲示板の5/10秒更新、混雑率％の復活。これらは事故を防ぐため個別に検証する。
