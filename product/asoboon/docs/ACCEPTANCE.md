# ASOBooN Model RC2 本番受入基準

## Customer
- 現地受付枠だけ表示される
- WEB/時間指定予約枠はお客様の現地受付画面に表示されない
- テスト枠・待機者専用枠・待ち項目ID 0042は表示/作成できない
- 1受付10名超をフロント/サーバー双方で拒否
- 保護者1名につき子ども3名超をフロント/サーバー双方で拒否
- 0〜5か月無料が料金計算へ加算されない
- 18:00〜18:59受付不可
- 19:00以降の翌日受付は `AIRWAIT_NEXT_DAY_RECEPTION_READY=1` を確認するまで開かない
- 確定直前に最新の受付状況をサーバーで確認し、残り0なら作成しない
- 同一requestIdが完全同時に届いても受付が重複しない
- 受付済み端末は同一営業日の重複受付を案内しない
- 顧客状態照会は reserveId + statusToken が一致した予約だけ返す
- 過去日の同一受付番号だけを理由に現在予約をキャンセル扱いしない

## Staff
- 現地受付とWEB/時間指定予約を両方表示する
- `Txxx` は時間指定、`Fxxx` は割込、数字のみは通常受付として区別する
- `T208` と `208` を絶対に同一予約としてID連携しない
- 現地受付だけID連携を必須とし、WEB/時間指定の未連携を異常扱いしない
- 現地受付の先頭が本当にID未連携なら後続を追い越さない
- 100組超でも全件取得できる
- status=4 は「対応中」と表示し、呼出中件数には含めない
- AirWAIT呼出API未確認時はAUTO ON不可
- WEB/時間指定予約のreserveId取得方法未確認時もAUTO ON不可
- API異常時はAUTO OFFへ安全停止

## Server AUTO
- お客様画面の表示対象ではなく、運用対象の待ち項目を取得する
- WEB/時間指定予約もAUTO候補に含む
- 同じ開始時刻のWEB枠＋現地枠を1つの入場回として束ねる
- 1入場回の呼出中プールは合計最大10組
- 受付開始前は呼ばない
- 呼出前に対象入場回を再取得し、スタッフ手動呼出を反映する
- 呼出API成功後、AirWAIT一覧反映が遅れても一定時間は呼出中として数える
- 呼出中が減ると次周期で補充する
- 18:00以降は呼出しない
- iPadスリープ/ページ終了中もサーバートリガーで継続する
- 同時実行はScriptLockで排他する
- 開始時刻を解析できない待ち項目は呼ばず、イベントログへ記録する
- WEB/時間指定予約のreserveIdを解決できない場合は追い越さずAUTO全体を安全停止する

## External AirWAIT Gates — すべて確認必須
- `reserve/call` がASOBooNのAPIキー/店舗で利用可能
- 現行 `callingMethodType` が確定
- WEB/時間指定予約（T番号）の `reserveId` 取得方法が確定
- 19:00以降に `reserve/create` した受付が翌営業日扱いになることを実環境で確認
- AirWAIT側の上限到達時に同時受付が安全に拒否されることを実環境で確認

## Security / Operations
- GitHub/HTML/JSにAirWAIT APIキーなし
- STAFF_KEYはScript Properties + 認証済み端末localStorageのみ
- reserveIdだけでは顧客受付状態を照会できない
- 呼出APIと外部予約ID取得の開放はScript Propertiesで明示制御
- 秘密情報ローテーション後に旧キーが無効であることを確認
- 1日通しのiPad/サーバーAUTO耐久試験を実施
- AirWAIT一時障害→復旧、通信断→復旧、GAS一時失敗→復旧を確認

## GA判定
上記項目がすべてPASSし、External AirWAIT Gatesが全て解消した時点のみ `ASOBooN Model 1.0 GA` とする。
