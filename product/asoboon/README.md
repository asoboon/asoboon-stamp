# ASOBooN Reception Model 1.0 RC2

ASOBooN向けの次期本番正本候補。現在の本番を壊さず `/product/asoboon/` に分離して開発する。

## 最上位仕様
`docs/MUST_REQUIREMENTS.md` を非交渉要件とする。MUSTを満たさない設計・実装・暫定運用は本番採用しない。

## 基本アーキテクチャ
- 予約・受付状態の正本はAirWAIT
- ミニアプリは日別枠制御、予約UI、マイ予約、呼出目安、自動呼出を担当
- AirWAIT標準自動呼出は使用しない
- AirWAIT APIキーはブラウザ/GitHubへ置かない
- 秘密情報保護が必要なAPI操作のみ薄いサーバーAPIを通す
- 受付処理や状態管理をGAS固有ロジックへ過度に依存させない

## ASOBooN MUST
- ミニアプリから場所を問わず予約可能。位置情報は不要
- 翌日分は前日19:00から予約開始
- AirWAIT側には使用枠を常設し、曜日・特定日ごとの予約可能枠はミニアプリ側で決定
- AirWAIT標準自動呼出はOFF、ASOBooN側で自動呼出
- 予約成功後に受付番号をミニアプリ端末へ保存
- マイ予約から呼出状況と呼出時間の目安を確認可能
- WEB予約＋ミニアプリ予約を同じ入場回として扱い、呼出中は合計最大10組を基本とする

## ASOBooN標準
- 1受付 合計10名まで
- 保護者1名につき子ども3名まで
- 大人600円 / 子ども900円
- 0〜5か月までの子どもは追加料金無料
- T番号（時間指定）、F番号（割込）、通常番号を別物として保持
- テスト枠、ご待機者専用枠、待ち項目ID 0042は運用対象外

## AirWAIT仕様上の未確定事項
 supplied `reserve/create` には予約日パラメータがない。そのため前日19:00から翌日分を作るには、AirWAIT側の正式な翌日/時間指定予約作成方法を確認する必要がある。

また、予約一覧APIでは呼出番号は取得できるが、現行仕様書ではWEB/時間指定予約の `reserveId` が返らない。呼出APIは `reserveId` 必須のため、WEB/時間指定予約のreserveId取得方法も確認必須。

## 安全ゲート
AUTO ONには少なくとも以下が必要:
- `AIRWAIT_CALL_ENABLED=1`
- `AIRWAIT_EXTERNAL_RESERVE_ID_READY=1`
- 入場回ごとのwaitTypeIdグループ設定完了

翌日予約の開放には:
- `AIRWAIT_NEXT_DAY_RECEPTION_READY=1`

すべて未確認状態では本番開放しない。

## デモ
- お客様: `./customer/?demo=1`
- スタッフ: `./staff/?demo=1`

デモはブラウザ内データだけで動作し、AirWAITへ接続しない。

## 本番移行条件
1. `docs/MUST_REQUIREMENTS.md` を満たすこと
2. AirWAITから reserve/call の現行仕様回答を受領
3. 外部APIから翌日/時間指定予約を作成する正式方法を確定
4. WEB/時間指定予約のreserveId取得方法を確定
5. 実waitTypeIdで日別枠制御と入場回グループを確定
6. テスト店舗/実環境で予約→保存→状態確認→AUTO呼出のE2E成功
7. `docs/ACCEPTANCE.md` の全項目PASS
8. 現行本番から段階切替

## 重要
- `T208` と `208` のような接頭辞違いを同じ受付番号として扱わない。
- WEB未連携を異常扱いしない。
- 現地/ミニアプリ予約だけ先行AUTOし、WEB予約を追い越す運転はしない。
- 「前日19:00予約」はMUSTであり、AirWAIT仕様が未確認だから要件を削るのではなく、正式な実現手段を確定する。
